# 多设备布局验收

日期：2026-10-19。本轮使用独立模拟数据库，未向正式数据库写入验收数据；仅修改网页 CSS 与小程序 WXSS。

## 已修改

- 手机管理页顶部改为真实分栏，长姓名与标题可换行，避免绝对定位覆盖。
- 手机表格改为字段名在上、内容在下，串码、徽章、操作按钮正常排列。
- 搜索输入独占一行，状态和查询按钮在下一行，避免中等宽度被挤压。
- 财务统计自适应列数，长金额可换行。
- 文本域限制在容器内，只允许纵向调整；按钮、输入及网格子项允许收缩。
- 弹窗限制视口宽高，内容过多时内部滚动，横屏可操作。
- 去掉网页320像素强制最小宽度，避免窄屏加滚动条后页面横向偏移。
- 师傅端标题可换行，统计与订单列表增加间隔。
- 小程序补充长名称、串码、按钮换行，底部安全区，以及平板字号和内容宽度规则。

## 实际浏览器检查

使用 Chromium 浏览器视口模拟，并非实体设备真机验收。

| 范围 | 尺寸 | 结果 |
| --- | --- | --- |
| 管理后台8模块 | 320×740、390×844、600×900、768×1024、1024×768、1280×800、1920×1080、844×390 | 共64组：62组未发现页面或控件越界；320宽财务与责任扣款发现水平偏移 |
| 入口、管理登录、超管登录、师傅登录 | 320×740、390×844、768×1024、1024×768、1920×1080、844×390 | 共24组，未发现页面横向溢出 |
| 师傅工作台及打开的订单详情 | 与管理后台相同8种尺寸 | 8组未发现卡片或控件横向越界 |
| 重新派单弹窗 | 320×740、768×1024、844×390、1280×800 | 四种尺寸均位于视口内；390高横屏弹窗高度366，内部滚动 |

后台模块包含订单派单、人员管理、师傅等级、财务流水、责任扣款、机型方案、操作日志、我的资料。订单详情与转派弹窗实际打开检查，未提交转派。

320宽偏移原因已现场定位：根元素宽320，横向滚动偏移约15.33像素；竖向滚动条占用宽度后强制最小宽度撑大页面。已取消该最小宽度。随后浏览器工具连接中断，未完成此修复后的64组复测。师傅统计间距的最后修改同样未复测。

## 验收限制

- 小程序修改仅做源码审查，未在微信开发者工具、微信真机或平板真机验证。
- 未验证 iOS Safari、Android 微信内置浏览器、软键盘及设备字体放大；长姓名等极端数据未做完整实测。
- 本轮没有修改金额、结算或权限逻辑，未重复执行金额随机压力测试。
- 不应将本报告视为所有实体设备均已通过验收。剩余工作为浏览器恢复后的最窄屏复测及微信真机检查。
